The Studio runs in the browser. It needs an RPC endpoint and a Solana wallet: the
program derives every organization from the wallet that created it, so a wallet session is the
sign-in step.

## Prerequisites

- A modern browser (Chrome, Brave, Firefox, or Safari).
- An RPC URL. The public devnet endpoint works for a first look; a dedicated provider is better for real work.
- A wallet such as Phantom, Solflare, or Backpack. The Studio cannot read accounts without one.

## Run the Studio locally

```bash
pnpm install
pnpm dev:web
```

The app starts at `http://localhost:3001`. Marketing pages are prerendered; the Studio lives under
`/studio` and runs in the browser against the deployed devnet program.

## Sign in with a wallet

Signing in is connecting a wallet. Without one, every `/studio/org` page redirects to `/studio/auth`.

1. Open the Studio. Guests land on the sign-in page.
2. Choose **Connect wallet**. The Studio lists wallets from Wallet Standard, and also detects an
   injected Phantom, Solflare, or Backpack provider.
3. Approve the connection in the extension. Peridotbase receives only your public address.
4. Create an organization and a project. Both are Solana accounts owned by your wallet, and the
   next visit lists them automatically.

<Warning>
	Never enter a seed phrase or private key into the Studio. There is no field for one, and no
	legitimate Peridotbase screen will ask.
</Warning>

## Try the demo (no wallet, no program)

```bash
pnpm dev:web:demo
```

Demo mode opens the full Studio on labeled sample data: tables, schema, the query runner,
indexes, the visualizer, and the workspace. Every screen carries a **Demo preview** banner and
nothing is read from or written to Solana. To return to the real client, restart with
`pnpm dev:web`.

## Choose a cluster and RPC endpoint

The workspace settings let you pick a cluster and an RPC URL:

| Cluster        | Typical use                    |
| -------------- | ------------------------------ |
| `mainnet-beta` | Production data                |
| `devnet`       | Development and testing        |
| `testnet`      | Validator and protocol testing |
| `localnet`     | A validator on your machine    |
| `custom`       | Any compatible RPC provider    |

The Studio checks the endpoint with a `getSlot` and `getVersion` call. A reachable endpoint shows its slot height in the workspace header; an unreachable one explains what failed instead of silently timing out.

## Open a database

The workspace lists the databases the open project owns on devnet. The first visit creates the
organization, project, and database catalogs your wallet owns, so approve those transactions.

<Note>
	Table and column renames, column-type changes, column drops, and index drops have no program
	instruction yet, so those controls report **pending integration** instead of pretending to
	succeed.
</Note>
